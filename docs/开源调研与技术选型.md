# Windows 默认网关自动切换：开源调研与技术选型

调研日期：2026-10-19（北京时间）。

## 结论

建议自行实现一个 C# / WinForms Windows 托盘工具，不直接采用现有候选程序，也不以它们作为整项目 Fork 的基础。

本次检索发现的相关工具分别覆盖网关手动切换、网络配置预设或连通性监测；没有找到经核实能够直接满足“选择指定网卡 + 自定义主备网关 + 主网关失联后自动切换”的完整程序。此结论限于本次检索与核查范围，并不表示 GitHub 上绝对不存在其他实现。

最接近的界面参考是 NetProfile Switcher；最接近的轻量托盘参考是 GateSwitchWay。但两者都需要重新开发关键的检测和自动切换逻辑，且网关操作层也有需要改造的地方。对本项目而言，直接实现范围明确的专用工具，比保留整套预设、DNS、IPv6等功能再修改更合适。这是基于功能缺口和源码的工程判断，尚未通过完整原型开发对比工时。

## 需求解释

本次按“同一张 Windows 网卡上的 IPv4 默认网关切换”理解：

- 用户选择要管理的网卡，显示网卡名称、当前 IPv4、当前网关。
- 主网关默认填写 `192.168.88.191`，备用网关默认填写 `192.168.88.1`，两项均可修改。
- 程序持续检测主网关；主网关持续失联、备用网关可用时，修改该网卡的默认路由。
- 所选网卡的 IP、子网掩码和 DNS 保持原配置。
- “主网关恢复后自动切回”作为独立可选功能，默认关闭，避免把未提出的行为设为强制要求。

这里的“网卡地址可选择”解释为选择网卡，并在该网卡有多个 IPv4 地址时选择检测使用的本地地址；不默认增加修改电脑自身 IP 的功能。

## 两个主要候选的源码依据

### GateSwitchWay

核查版本：`622223586349060e2f4f4278100f4a42745d0ebd`。

在 [NetworkHelper.cs](https://github.com/lsd-techno/GateSwitchWay/blob/622223586349060e2f4f4278100f4a42745d0ebd/NetworkHelper.cs) 中：

- 读取网络信息时遍历接口，遇到第一个在线且非回环的网卡后退出；不等于用户指定的网卡。
- 添加路由时从所有在线物理接口取得索引，没有传入用户选择的单一接口身份。
- 删除旧路由仅按下一跳筛选，没有同时限定接口和默认路由前缀；在复杂路由环境中可能影响范围外的路由。
- 命令执行辅助逻辑还存在只按目标前缀查询、删除路由的分支，需要重新审查和限制作用范围。

这些是静态源码检查发现的问题，未运行程序复现。其 [MainForm.cs](https://github.com/lsd-techno/GateSwitchWay/blob/622223586349060e2f4f4278100f4a42745d0ebd/MainForm.cs) 存在状态刷新定时器；不能把“刷新当前状态”理解成“检测网关故障并自动切换”。README 的 Auto Alter 指启动时应用备用配置。

## 建议实现方案

采用 C# + WinForms，首版提供图形配置和托盘常驻；网络读写使用 Windows 自带的网络 API 或 NetTCPIP 命令。暂不依赖上述第三方应用源码。

首版功能建议：

1. 网卡下拉选择与刷新，显示名称、IPv4、当前默认网关；保存网卡 GUID，运行时重新解析接口索引。
2. 主网关和备用网关可填写，检查合法 IPv4、地址不同、网关能从所选网卡直接到达。
3. 可配置探测间隔、超时、连续失败次数；提供“仅检测”模式，方便上线前验证。
4. 开始/停止监控、手动切换、当前主备状态、最近一次探测结果和切换日志。
5. 切换前备份目标网卡的相关路由；执行后读取验证；失败时尝试回滚并明确记录结果。
6. 提供恢复原配置入口、可选恢复后切回、切换冷却时间。
7. 托盘运行；需要无人登录持续运行时，再将监测核心做成 Windows 服务，界面只负责配置与状态展示。

建议初始参数为每 3 秒一轮、单次超时 1 秒、连续失败 3 次触发故障判断、切换冷却 30 秒。它们是待实测调整的建议值，真实切换耗时还取决于探测调度、ARP 和系统路由操作，不能直接承诺固定秒数。

状态处理：

- 主网关正常：保持主网关。
- 主网关连续失败，备用可用：切换备用并验证结果。
- 主备均不可用：保留当前路由，记录故障，继续探测，避免反复切换。
- 主网关恢复：自动切回关闭时继续使用备用；开启时，在连续成功且满足冷却条件后切回。
- 网卡断开、地址消失或接口身份无法确认：暂停修改路由，等待网卡恢复。

## 网络实现必须处理的边界

- 只操作所选网卡的 IPv4 默认路由，所有删除和修改都必须限定接口、地址族、目标前缀及被管理的下一跳，不删除其他网卡或 VPN 的路由。
- 检测必须使用所选网卡的本地 IPv4，并确认实际路由经过该接口。多张网卡连接相同网段时，不能只凭普通 Ping 成功就判定目标接口可用。
- Ping 成功只说明网关响应 ICMP，不保证网关的外网转发正常；Ping 失败也可能是设备禁止 ICMP。首版按“网关设备在线”检测，部署前确认其回应方式；若需要检测“经该网关上网正常”，应另做绑定该路径的外网探测。
- 保留现有 DHCP 地址与 DNS 配置，处理 DHCP 续租重新注入默认路由、网卡重连和系统重启。程序应先明确管理临时路由还是持久配置，不能让两种状态相互覆盖。
- 仅更改 IPv4 网关不会接管 IPv6 流量；界面应明确显示管理范围。
- 多网卡场景下，某网卡有默认路由不代表系统流量一定使用它，还受路由及接口度量值等因素影响。应显示实际生效路径，不自动改动其他网卡来强制抢占。
- 修改路由需要管理员权限。首版可通过一次提权启动托盘程序；设置自启时不能假设普通启动项能自动取得所需权限。
- 切换可能中断已有连接；若 DNS 仍指向失联的主网关，单改默认网关后可能仍无法解析域名。DNS 是否随切换改变应作为后续明确配置项。

微软官方依据：[New-NetRoute](https://learn.microsoft.com/en-us/powershell/module/nettcpip/new-netroute?view=windowsserver2025-ps) 支持按接口添加默认路由并区分当前与持久存储；[IcmpSendEcho2Ex](https://learn.microsoft.com/en-us/windows/win32/api/icmpapi/nf-icmpapi-icmpsendecho2ex) 支持指定探测源 IPv4 地址。
